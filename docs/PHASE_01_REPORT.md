## 环境与上游兼容问题

1. Poetry 2.2.1 放在明确的本地工具 venv，游戏依赖安装到指定 Conda 环境。保留上游锁文件及源码 commit。
2. 用户 Python 3.11 site-packages 中有其他项目依赖；启动使用 `-s` 和 PYTHONNOUSERSITE=1，隔离后 pip check 无冲突。
3. Ares 和 sc2_helper 需按模板将子模块源码目录加入模块路径，Cython 与 Rust 组件已导入验证。
4. 新 SDK 仍会过滤静态枚举外的能力编号，4135 单位订单可复现 KeyError。项目内补充当前引擎技能数据，保留未知原编号，不修改安装目录或子模块源码。
5. Ares BuildingManager 对已建成基地的“占位”判断早于“任务已完成”判断，导致完成二矿的工人被重派到第三处。通过项目内同名管理器扩展、官方 Hub 自定义 manager 接口，在原逻辑前回收已完成的基地任务。保留 canonical 类名以满足 mediator 的路由约定，回归测试覆盖回收时机、计数、角色及其他任务保留。
