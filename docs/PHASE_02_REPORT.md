# P2：LLM 战略层

状态：P2受限战略首版工程验收通过，保留本地标签 `baseline-llm-v1`；正式战略强度评估仍未完成。

本阶段在 P1 的 Ares Marine 规则基线上，接入用户已有的 DeepSeek API。目标是验证战略计划能够在后台生成、受控接管且故障时保持游戏运行。RL 微操、BC 数据采集和 PPO 训练属于后续阶段，尚未实现。

## 结构与边界

`SC2 官方协议 → Ares/BurnySC2 → 每1秒可见局面摘要 → 单后台HTTP请求 → 严格战略校验 → Director → RuleBot 的经济/作战目标钩子 → Ares 宏观行为与单一 Marine 命令出口`。

- `run_rule.cmd`：默认保持完整实时规则版，不导入 LLM 客户端、不读取密钥、不联网。
- `run_shadow.cmd`：记录候选计划和有效期，经济与军队仍完全由规则控制。
- `run_llm.cmd`：允许有效计划修改工人目标、基地目标和主力任务。具体建造、采矿和单位命令仍在本地执行。
- `stance` 是战略意图标签；实际执行以 `economy`、`squad_tasks`、`attack_gate` 为准。生产只支持 `marine_basic`，研究优先级必须为空，不接受模型代码、技能编号或任意坐标。
- 单一主力 `main` 可执行 attack / defend / rally / retreat。进攻目标 `enemy_main` 在本地解析为已知敌建筑，清理后搜索扩张点；其他任务只能指向 own_main / own_natural。二矿未就绪时回到主矿。
- 工人目标16–48，实际目标受每个就绪基地22工人上限约束；基地目标1–2。不会通过降低目标删除已有工人或基地。扩张仍经过120秒、20工人与有期限的矿物预留机制。
- 基地25距离内出现可见敌军/敌工人时，规则紧急防守优先于模型作战命令，不等待下次 API 返回。

## 节奏、校验与故障行为

| 参数 | 当前实现 |
|---|---|
| 摘要 | 每1秒游戏时间；当前可见敌方计数和最多40条120秒内 last-seen 事实 |
| 查询 | 每15秒游戏时间尝试，距上次至少5秒实际时间 |
| 并发/积压 | 最多1个真实后台请求；线程忙或结果未取走时不提交 |
| 上限 | 默认60次/局；`--llm-max-calls` 可调，0表示不发请求 |
| 超时 | HTTP连接5秒/读取15秒；游戏线程在20秒实际时间后宣布逻辑超时并丢弃迟到结果 |
| 观测有效期 | 从输入采集算45秒游戏时间；超龄结果不接管 |
| 承诺期 | 已采用意图至少30秒游戏时间，新意图先 pending；同意图可续期，不重置承诺起点 |
| 退避 | 错误后5/10/20/40/60秒实际时间；没有后台排队重试 |
| 输出 | JSON mode，max_tokens=768；本轮关闭 thinking，无嵌入模型和向量检索 |

20秒为主循环的结果接受截止时间。requests 的连接/读取超时并非整个网络操作的硬性总时限；若底层网络迟迟不退出，旧线程仍占唯一槽位，主循环继续本地规则/有效计划，不另起线程或积压。游戏结束不 join 网络线程，后台 daemon 随进程退出。

严格拒绝额外/缺少字段、重复JSON键、NaN/Infinity、布尔冒充整数、范围错误、错误 request_id/snapshot_seq、不支持的生产科技、非法 squad/目标组合。仅解析 `content`，不保存提供方推理内容。API失败保留尚未到期的计划，失效后回到规则；本地紧急防守始终可抢占。进度事件记录等待兵力、紧急防守覆盖、经济目标达成、计划 pending/active/renewed/expired；持续防守/集结任务不会伪称“完成”。整局结果另行记录。

首版采用周期查询，没有实现计划中提到的重大交战/科技发现事件提前查询。输入尚未含完整损失交换统计和采矿效率估计；目标完成通过局部满足条件与整局结果表达，尚无通用的逐目标 completed/cancelled 状态机，也不接管已投入的科技或复杂兵种。这些作为后续增强保留，不影响本轮受限 Marine 战略链路；不将整个规划的所有条目记作已完成。

## 依赖和私有配置

继续使用 `sc2-ares-runtime`、Python3.11 和原锁定 Ares。请求使用锁文件已安装的 requests2.32.3，未增加依赖、修改上游子模块或 site-packages。P1 标签 `baseline-rule-v1` 保留。

已有 DeepSeek 三项配置复制到被 Git 忽略的 `.env.local`，环境变量优先。密钥不进入命令行、manifest、报表或记忆。客户端异常只记录错误类别/状态码，模型正文若复述密钥会先遮盖；不记录服务器错误正文。迁移时使用 `.env.example`。

接口依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。采用官方 JSON mode，并额外执行本地约束校验；合法 JSON 本身不足以保证战略可执行。

## 操作与关闭

所有命令从 `D:\CODE\sc2-ares-llm-rl` 运行。

| 项目 | 前置依赖 / 应用方式 | 启动与验证 | 当前状态 / 关闭方式 |
|---|---|---|---|
| Ares规则钩子 | 原运行环境；代码已应用 | `run_rule.cmd` | 默认保持规则；P1标签保留 |
| LLM影子 | 已有DeepSeek配置；无新安装 | `run_shadow.cmd` | 真实120秒验证通过；结束游戏或Ctrl+C关闭 |
| LLM接管 | 同上 | `run_llm.cmd` | 完整实时获胜/工程验证通过；切回 `run_rule.cmd` 关闭LLM |
| 调整调用上限 | 同上 | `run_llm.cmd --llm-max-calls 10` | 默认60；设0不调用API |
| 单测 | `conda activate sc2-ares-runtime` | `python -s -m unittest discover -s tests -v` | 25项通过；无游戏/API调用 |
